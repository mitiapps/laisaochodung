# laisaochodung

Browser driving game on Vietnamese traffic law. Code, comments and docs in English; every game UI
string in Vietnamese (`{vi, en?}` texts, `en` left empty). Architecture:
[docs/architecture.md](docs/architecture.md).

## Toolchain

- Node 24.15 or later and npm 11; one lockfile (`package-lock.json`). New dependencies go through
  the maintainer, never ad hoc.
- Plain JavaScript with JSDoc (TypeScript-flavour types, linted by eslint-plugin-jsdoc). No
  TypeScript files.
- Gates before handing work over: `npm run lint`, `npm test`, `npx vite build`.

## Purity guard

`src/contracts/`, `src/geometry/`, `src/world/`, `src/testing/`, `src/rules/`, `src/scoring/` and
`src/map-query/` are pure: they run unchanged in the browser, in Node tests and in build scripts.
ESLint (`eslint.config.js`) rejects in them:

- imports of `three`, `@dimforge/*`, `svelte`, `yaml`, `node:*`, `fs`, and any path into
  `src/physics`, `src/sim`, `src/render`, `src/ui` or `src/game`;
- `Math.random`, `Date.now`, `performance`, `window`, `document`, `requestAnimationFrame`.

Dependency direction: `src/geometry/` imports nothing; `src/world/` only `src/contracts/` and
`src/geometry/`; `src/testing/` only those plus `src/world/`. Colocated `*.test.js` files are
exempt. `src/testing/purity-guard.test.js` proves the guard fires.

## Data first

- Penalties live once, in the clause table keyed by `D6.3.a`-style ids; rules point at clauses.
  A law change edits one record.
- Rules, clauses, speed defaults, sign meanings and maps are data files compiled to JSON at build
  time. Logic never hard-codes a fine, a point value, a limit or a sign meaning.
- Every legal number comes from a fetched, quoted citation. Unverified data carries
  `verified: false`; thresholds the game invented carry `paramBasis: design`.
- `data/signs/signs.yaml` is the one list of sign codes the game uses.

## Contracts

The JSDoc typedefs in `src/contracts/` are the interfaces between modules (frames, maps, rules,
scores, HUD, module factories). Change them only through the maintainer, in one change that
updates the fixtures in `tests/fixtures/` too. `assertFrame` and `assertMap` validate frames and
maps at boundaries.

## File ownership

Work is split by directory; touch only the directories you own for the task:

| Area | Directories |
| --- | --- |
| Contracts and shared pure logic | `src/contracts/`, `src/geometry/`, `src/world/`, `src/testing/`, `data/signs/`, `tests/fixtures/`, root config |
| Rules and scorer | `data/legal/`, `data/rules/`, `data/scoring/`, `scripts/rules/`, `src/rules/`, `src/scoring/`, `src/map-query/` |
| Physics and sim | `src/physics/`, `src/sim/` |
| Rendering and assets | `src/render/`, `public/models/`, `public/signs/`, `data/credits/` |
| Maps | `scripts/maps/`, `data/maps/` |
| UI | `src/App.svelte`, `src/app.css`, `src/ui/`, `src/config/` |
| Integration | `src/game/`, `src/main.js` |
| Scenario and browser tests | `tests/scenarios/`, `tests/e2e/` |

## Fixtures

`tests/fixtures/frames-straight.json` is generated by the frame builder. After a deliberate change
to the builder or the minimal map, regenerate it with
`UPDATE_FIXTURES=1 npx vitest run src/testing` and review the diff.
